Proofmark uses Creditcoin Universal Smart Contracts (USC) as the trust layer for cross-chain compliance READs. USC turns a KYC/AML lifecycle event on Ethereum into state that a Creditcoin smart contract can verify and enforce without trusting a Proofmark-operated oracle.

`ComplianceSource` emits `MarkIssued`, `MarkRevoked`, `SanctionDenied` and roster-epoch events on Ethereum Sepolia. The deployment preflight reads the supported source-chain key from Creditcoin's ChainInfo precompile through `@gluwa/usc-sdk`. A durable worker waits for USC to attest the source block, requests the Merkle inclusion and continuity proof from the proof-builder service and submits that public proof material to `ProofmarkASC` on Creditcoin CC3.

`ProofmarkASC` calls `verifyAndEmit` on Creditcoin's native `BlockProver` precompile and uses `EvmV1Decoder` from `@gluwa/usc-contracts` to decode the verified Ethereum receipt. It accepts events only from the configured USC chain key and source contract, then orders lifecycle changes by proven block height, transaction index and log position. An event from another chain is rejected, and an old issuance proof cannot restore a credential after a later revocation.

Creditcoin applications consume the materialised state through `ProofmarkRegistry.isVerified(wallet, policyId)`. Each asset binds to a frozen policy for verification methods, assurance, issuer, regime, jurisdiction, age and roster freshness. Our reference tokenised credit note calls that READ for both sender and recipient during transfer.

The worker transports proof but never creates a replacement compliance claim. Any submitter can carry the same proof while the Ethereum event remains authoritative. This is why compliance is a strong USC use case: the state changes relatively slowly, may be checked on every transfer and must preserve source authenticity, lifecycle order and revocation. One USC-verified credential can serve many policies and assets without copying personal data or turning a relayer key into the compliance authority.

The public v2 run demonstrates both supported transport shapes. Sepolia transaction `0xcad8aa…c40` contains two issuance events that USC materialised atomically in Creditcoin transaction `0xb490b6…2392`. Sepolia transaction `0x06a61a…e23c` publishes an issuer-approved Merkle roster root with a source-cutoff lifetime, and USC materialised that epoch in Creditcoin transaction `0xf2bda1…7741`. After caching the two current membership witnesses, `GatedRwaNote` minted 100 KPCN and transferred 40 KPCN between eligible holders. The same transfer call to a never-issued address reverts with `RecipientNotVerified`. All contract addresses, source and relay transactions, runtime hashes, the epoch root and the asset transaction are recorded in `deployments/cc3-testnet.json`.
